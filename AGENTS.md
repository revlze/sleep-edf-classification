Перед изменениями проверяй фактическое состояние репозитория. Создавай модули и директории по мере необходимости; не добавляй пустые заготовки, лишние зависимости и абстракции. Не переписывай работающий код без конкретной причины.

## Общение и достоверность

Сложные объяснения пиши связным текстом; существенные формулы оформляй отдельными блоками математической разметки.

## Python и зависимости

Используй `uv` для управления окружением, зависимостями и запуска Python. Зависимости объявляй в `pyproject.toml` и фиксируй в `uv.lock`. Проверяй совместимость с объявленной версией Python; не меняй её без обоснования. Добавляй инструменты только при реальной необходимости:

- OmegaConf — загрузка YAML-конфигураций моделей и экспериментов.
- MLflow — локальная история экспериментов, параметров, метрик и артефактов.
- Polars — табличные данные; Pandas допустим для совместимости с библиотеками.
- NumPy и SciPy — численные вычисления, статистика и обработка сигналов; MNE-Python — работа с EEG/EDF.
- scikit-learn — preprocessing, разбиения, метрики и классические модели.
- LightGBM и XGBoost — бустинг; PyTorch — нейросети; Optuna — подбор гиперпараметров.
- Matplotlib и Seaborn — графики; tqdm — прогресс длительных операций.
- Ruff — линтинг и форматирование; pytest — проверки критичных компонентов.

Для поставленных NPZ не вводи промежуточное преобразование в EDF без необходимости. Используй `pathlib`, явные пути и type hints для основных функций. Предпочитай небольшие функции лишним классам; не создавай универсальные функции с множеством ветвлений. Комментируй неочевидную логику и используй возможности существующих библиотек.

## Организация кода

Сохраняй плоскую структуру `src/`:

- `data.py` — загрузка сигналов, меток и метаданных.
- `preprocessing.py` — обработка сигналов и извлечение признаков.
- `models.py` — создание моделей.
- `training.py` — обучение.
- `evaluation.py` — валидация и метрики.
- `inference.py` — предсказания и формирование итогового CSV.

`notebooks/` используй для EDA, запуска экспериментов, визуализации и анализа. Переиспользуемую логику выноси в `src/`; не дублируй её в notebooks. `configs/` хранит YAML, `tests/` — содержательные проверки, `docs/` — документацию, `artifacts/` — локальные результаты, `submissions/` — файлы предсказаний. Создавай эти файлы только вместе с соответствующей функциональностью.

## Конфигурации и эксперименты

Для каждой модели используй отдельный YAML в `configs/`, например `baseline.yaml`, `lightgbm.yaml` или `cnn1d.yaml`. Включай необходимые название и тип модели, гиперпараметры, настройки обучения и preprocessing, seed и пути. Загружай YAML через OmegaConf и передавай параметры функциям. Не хардкодь настройки эксперимента и не дублируй их без необходимости. Добавление модели должно требовать минимальных изменений существующего кода.

Используй стандартную локальную конфигурацию MLflow без обязательного сервера. Логирование должно работать независимо от запуска UI. Сохраняй разрешённую конфигурацию OmegaConf, гиперпараметры, seed, стратегию разбиения, версию данных, метрики и время обучения. Для нейросетей логируй метрики по эпохам. Добавляй необходимые графики и артефакты; веса сохраняй, когда они нужны для воспроизведения или инференса. Autologging применяй там, где он упрощает код.

MLflow — основной источник истории экспериментов. Не усложняй pipeline отдельной системой учёта. Локальные хранилища MLflow, логи и модели исключай из Git. В README добавь команды запуска эксперимента и MLflow UI с согласованными настройками хранилища.

## Данные и валидация Sleep-EDF

Формат поставленных данных сверяй с `data/data_description.md`. Не считай характеристики других редакций Sleep-EDF характеристиками этой поставки.

- Используется редакция `full_psg_v1`: один NPZ соответствует записи. Ключи — `x`, `ids`, `epoch_index`, `fs`, `channel_names`.
- Одна эпоха длится 30 секунд при 100 Гц. `x` имеет тип `float32` и форму `(N, 3000, 3)`, амплитуды заданы в микровольтах.
- Порядок каналов: `EEG Fpz-Cz`, `EEG Pz-Oz`, `EOG horizontal`. Проверяй `channel_names`; ЭОГ не является третьим каналом ЭЭГ. Перевод в вольты и перестановку осей для модели выполняй явно.
- Классы: `0 = W`, `1 = N1`, `2 = N2`, `3 = N3`, `4 = REM`. Не добавляй отдельные классы для исключённых Movement/unknown эпох.
- Соединяй сигналы с `labels.csv` по `id`. Проверяй уникальность идентификаторов, формы, конечность значений, частоту, соответствие числа сигналов и меток и распределение классов.
- Не смешивай текущие NPZ, метки и идентификаторы с кэшами прежней обрезанной редакции. Кэш должен учитывать версию данных и параметры preprocessing.
- Контекстные окна и сглаживание должны учитывать границы записей и разрывы `epoch_index`. Соседние строки массива не обязательно являются соседними эпохами исходной записи.

Сохраняй выданное разделение по испытуемым. Для собственной CV внутри обучающей части группируй по `subject_id`, учитывая несколько записей одного человека. Случайное разбиение отдельных эпох неприемлемо. Все обучаемые преобразования выполняй с `fit` только на тренировочной части соответствующего fold. Это касается нормализации, отбора признаков, подбора гиперпараметров и других этапов pipeline.

Основная метрика — macro-F1. Дополняй её метриками отдельных классов и матрицей ошибок. Различай результаты CV, выданной валидации, проверки после выбора настроек и Kaggle; не называй их взаимозаменяемыми или независимыми, если это не так. Фиксируй seed для используемых генераторов и существенные ограничения воспроизводимости.

При использовании предобученных весов фиксируй модель, источник, версию checkpoint и преобразование входа.

Итоговый CSV должен иметь колонки `id,label`, допустимые целочисленные классы и точно сохранять идентификаторы и порядок строк `sample_submission.csv`. Связывай предсказания с конфигурацией, версией данных и состоянием модели, из которых они получены.

Поддерживай `.gitignore` вместе с появлением соответствующих файлов; исходный код, документация, конфигурации и `uv.lock` должны версионироваться.
